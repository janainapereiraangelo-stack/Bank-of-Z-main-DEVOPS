✔ Integração correta com DBB preview O script executa DBB em modo preview para gerar a build list e usa exatamente esses arquivos no scan — evitando varrer fontes não impactados pela mudança.
⚠ Arquivo de config ZCodeScan fora do repositório SCAN_CONFIG_FILE aponta para $HOME/zcs_config_file.yml — um arquivo externo ao repositório. Se ausente, o scan é silenciosamente pulado (exit 0). Isso pode mascarar falhas em ambientes novos.
Recomendação: versionar um arquivo de config base no repo em zcodescan/ com fallback explícito ou erro caso não exista.
⚠ RC=255 tratado como erro, mas RC -1 pode não ser detectado corretamente A lógica [ "$rc" -eq 255 ] || [ "$rc" -lt 0 ] pode falhar em shells sem aritmética signed. Testar com bash -c '[ -1 -lt 0 ]' em z/OS USS confirma o comportamento esperado, mas vale validar no ambiente de produção.

✔ Skip automático se não há pacote Se PACKAGE_URL estiver vazio ou "NONE", o deploy é pulado graciosamente — correto para mudanças sem impacto em build.
⚠ Typo no log da tarefa task-wazi-deploy.sh (linha 153) O loop de log usa "[GENERATE-${APP_BASE_NAME} $line" — falta o colchete de fechamento ]. Embora não quebre a execução, suja os logs de CI.
Correção: substituir por "[GENERATE-${APP_BASE_NAME}] $line".
🔴 Falha silenciosa no finalize_results (tar de logs deploy) O bloco finalize_results no deploy cria o tar com tar cf "$LOG_TAR" "logs", mas o diretório de trabalho nesse momento é $outputDir (linha 59: cd "$outputDir") e os logs são salvos como wazideploy*.log diretamente nesse diretório — não em um subdiretório logs/. O tar resultante provavelmente ficará vazio ou falhará.
Recomendação: ajustar para tar cf "$LOG_TAR" -C "$outputDir" . 2>/dev/null || true ou criar corretamente o subdiretório logs/.

4 · GitHub Actions — Workflow CI/CD

WorkflowTriggerEtapas
PR.yml PR opened / reopened / synchronize controller → setup (chama Setup.yml)
Setup.yml workflow_call (reutilizável) clone repo para USS → full-install → verify-installation
⚠ URL hardcoded no Setup.yml bozFrontendUrl: http://9.47.80.84:9081 está hardcoded — idealmente deveria ser uma variável de repositório (vars.BOZ_FRONTEND_URL) para facilitar portabilidade entre ambientes.
🔴 Nenhuma pipeline de CI executa ZCodeScan + DBB + Wazi Deploy em sequência Os workflows do GitHub Actions (PR.yml, Setup.yml) executam apenas install/verify. A pipeline completa scan-build-and-deploy é orquestrada pelo pipeline-remote.sh / pipeline-common.sh, mas não está mapeada em nenhum workflow YAML do GitHub. Isso significa que a esteira completa não é acionada automaticamente em PRs.
Recomendação: criar um workflow que invoque pipeline-common.sh scan-build-and-deploy via SSH (similar ao Setup.yml) para PRs ou merges para main.
